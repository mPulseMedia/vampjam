A · Get three things from Twilio
Twilio is the service that actually sends the text message. You need an account SID, an auth token, and a phone number to send from.
Sign in to Twilio
  • Go to console.twilio.com.
  • If you have never used it: sign up, and take the free trial. A trial can only text numbers you have verified — fine for testing with your own phone, but you will need to add a card before it can text anyone else.
You should land on a page headed Account Info or Account Dashboard.
Copy the Account SID
  • On that same page, find Account SID. It starts with AC and is a long string of letters and numbers.
  • Copy it. Paste it somewhere for a minute — Notes, or a scratch message to yourself.
Copy the Auth Token
  • Just below the SID: Auth Token, hidden behind a Show or an eye icon. Click it to reveal, then copy.
  • This one is a password. Do not paste it into a chat, including to me — it only ever goes into the Cloudflare box in step D3.
Get a phone number to send from
  • Left menu: Phone Numbers → Manage → Active numbers.
  • If a number is listed, copy it. It looks like +14155551212 — keep the +1.
  • If the list is empty: Buy a number, tick SMS in the capabilities filter, search, and buy one. About $1.15 a month, plus roughly a cent per text.
If it asks about a campaign or A2P 10DLC: that is US business registration for bulk texting. For a handful of texts to people you know you can usually skip it and come back if Twilio complains. If it blocks you outright, tell me and we will switch this to email instead — the rest of the setup is identical.
B · Make the worker
A "worker" is a small program that runs on Cloudflare. This one checks who is on your list and asks Twilio to send the text.
Open Cloudflare
  • dash.cloudflare.com, sign in.
  • Left menu: Compute (Workers), or Workers & Pages on the older layout.
You should see a list with vampjam-upload and vampjam-sync already in it. Those are the two you have. You are about to make a third.
Create it, and name it exactly
  • Create → Workers → Create Worker, or the Hello World starter if it offers one.
  • Name it vampjam-auth. Exactly that — the site is looking for that name.
  • Deploy. It will deploy a do-nothing program; that is expected.
C · Paste the real code in
Copy the code
  • Tap the button. It copies the whole program, about 200 lines. Nothing in it needs editing.
Replace what is there
  • On the vampjam-auth worker: Edit code — top right, sometimes behind a </> icon.
  • Click anywhere inside the code, then ⌘A to select all, then ⌘V to paste over it.
  • Deploy, top right.
You are done when the button settles and there is no red anywhere.
Check the address matches
  • Near the top of the worker page there is a URL ending .workers.dev.
  • The site expects vampjam-auth.crimson-dust-a18d.workers.dev.
  • If yours is different, paste it to me. One line for me to change — do not try to rename anything.
D · Give it five settings
Same worker: Settings → Variables and Secrets → Add, five times. Type matters: the first three are Secret, the last two are Text.
AUTH_SECRET — type Secret
  • Name: AUTH_SECRET
  • Value: a long random string you invent. Nothing depends on what it is; 40-odd characters of nonsense is right. Changing it later signs everybody out, which is the emergency lever.
TWILIO_SID — type Secret
  • Name: TWILIO_SID
  • Value: the Account SID from step A2. Starts AC.
TWILIO_TOKEN — type Secret
  • Name: TWILIO_TOKEN
  • Value: the Auth Token from step A3.
TWILIO_FROM — type Text
  • Name: TWILIO_FROM
  • Value: your Twilio number from A4, with the plus and country code: +14155551212.
SITE — type Text, then deploy again
  • Name: SITE
  • Value: https://vampsf.com
  • Then Deploy once more. Settings only take effect on a deploy.
E · Check it took
Reload this page
  • The box at the top asks the worker itself. All the dots should fill except the last two, which are about people and recordings — those come next.
If it still says the server is not there: the name is probably not exactly vampjam-auth, or the address in C3 is different. Send me the address and I will point the site at it.
F · Put people on the list
On the phone or the Mac, either is fine.
Add yourself first
  • Open Admin → Who can sign in.
  • Type your name and your own mobile number → Add.
  • The first number added becomes the administrator. That has to be yours.
Your number is never stored. The worker scrambles it with its own secret; the list keeps the scrambled version, your name, and the last four digits.
Prove it works, on yourself
  • Open Sign in, type your number, Text me a link.
  • The text should arrive in a few seconds. Tap the link.
  • You should land back here signed in, and the Sign in row at the foot of the session list should now show your name.
If no text arrives: the page will say what Twilio said. A trial account will refuse any number you have not verified — verify yours in the Twilio console under Verified Caller IDs, or add a card.
Add the others
  • Same box, one at a time: name and mobile number.
  • Nobody gets a text now. They only get one when they ask to sign in.
G · Close a recording
Make one private, and choose who
  • Admin → Private recordings.
  • Find the one you want and tap make private.
  • Tick each person who may open it. Untick to take it away — it takes effect on their next tap, no waiting.
Anything you do not touch stays open to anyone with the link, exactly as it is today.
See the gate
  • Open that recording in a private browser window, where you are not signed in.
  • You should get the sign-in panel instead of the player and the moments.
Worth knowing, again: the audio file still sits at a public address. Anyone who already has that exact address can still play it. This closes the door on the site; it does not lock the file. Say the word and I will do the lock — the audio moves behind the worker and the public address is switched off.
