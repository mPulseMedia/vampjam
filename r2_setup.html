Host the audio on R2

GitHub release assets keep failing to serve new uploads. R2 is reliable, streams on iPhone, and full quality.
You do the dashboard clicks; Claude does the code. Claude can't take your password or sign in for you. Stay logged into Cloudflare and follow the steps — when you reach a URL, paste it into the chat and Claude wires it into the app.
Steps
  1. Open R2 in Cloudflare
    dash.cloudflare.com → R2 (left sidebar). First time: R2 asks for a card on file even though the free tier is plenty — 10 GB storage and generous free egress.
  2. Create a bucket
    Click Create bucket. Name it vampjam-audio, leave location Automatic, Create.
  3. Upload the recording
    Open the bucket → Upload → drag in Sound.Union.2026-08-07.v2.m4a (it's in your vampjam folder). Wait for it to finish — ~137 MB.
  4. Turn on public access
    Bucket → Settings → Public access → R2.dev subdomain → Allow Access (type allow to confirm). Cloudflare shows a public URL like https://pub-xxxxxxxx.r2.dev.
  5. Send Claude the link
    Your file's URL is that public URL + the filename, e.g. https://pub-xxxxxxxx.r2.dev/Sound.Union.2026-08-07.v2.m4a. Paste it into the chat.
Then Claude points the Aug 7 page at the R2 URL, pushes, and you retest on your iPhone. From then on, new recordings go to this same bucket — no more GitHub release-asset roulette.
Notes. The r2.dev URL is rate-limited by Cloudflare and fine for a personal app; if it ever gets heavy we can put it behind a custom domain or your existing Worker later. Playback needs no CORS setup — the player loads audio directly.
